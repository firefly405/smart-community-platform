## 1. 文档目的

本轮审核只关注**演示可信度**，判定标准如下：

| 维度 | 通过条件 |
|------|----------|
| 状态闭环 | 主流程状态可完整流转，非法状态有拦截 |
| 数据闭环 | 关键动作会写入/更新关联表（缴费写 payment、核销写通行日志、装修押金写 deposit） |
| 展示闭环 | 列表/详情显示**可读名称**（业主名、房号、设备名），而非仅 ID |
| 统计闭环 | 首页/报表数字与真实业务数据一致（非硬编码、非错误算法） |
| UI 真闭环 | 前端按钮提示成功时，必须真实调用后端并刷新数据 |

3. **费用项目** → **生成账单** → **缴费** → 缴费记录出现流水  
4. **退款申请** → 审批通过 → 账单已付回退 + 负向 payment  
5. **报修** → 派单 → 处理 → 完成 → 评价  
6. **访客** → 审核通过拿二维码 → 核销 → 通行记录新增（注意设备 ID）  
7. **门禁权限** → 保存后重新打开仍在  
8. **快递** → 录入 → 取件  
9. **商品订单**（若手工构造带 items 的请求）→ 支付 → 发货 → 完成  

### 7.2 演示时需绕路 / 慎讲

| 路径 | 风险 | 话术建议 |
|------|------|----------|
| 装修→押金 | 审批不进押金 | 先在押金页手工建一笔，或跳过 |
| 车辆→车位占用 | 状态不联动 | 只展示车辆列表，不讲占用 |
| 商品下单库存 | 前端无明细 | 用接口工具带 items，或只演示状态按钮 |
| 服务预约 | 无页面 | 暂不演示 |
| 活动报名人数 | 不涨 | 只展示活动 CRUD |
| 社区投票 | 无投票 UI | 只展示投票配置 CRUD |
| 年龄分布图 | 硬编码 | 不展开讲算法 |
| 导出按钮 | 未开放 | 点了会失败提示，可主动说明 |

```text
登录 → 首页指标 → 业主绑房 → 账单生成/缴费/缴费记录
```
