# 一键启动项目

## 日常使用

双击项目根目录的 `Start-Community.cmd`，或桌面的“智慧社区启动器”快捷方式。

启动器依次检查 Java 17、Node.js、前端依赖和 MySQL，按需编译/启动后端、启动前端，验证页面和 API 代理后打开管理端与业主端两个登录页：

- 管理端：<http://127.0.0.1:5174/login>
- 业主端：<http://127.0.0.1:5174/community/login>

重复双击会复用健康服务，不重复启动、不强制结束任何已有进程。关闭启动器窗口不会关闭前后端。启动过程有互斥保护，同一时间只运行一个启动器。

## 环境与配置

启动器会先一次检测并列出本机环境，生成中文报告 `.runtime/launcher/environment-report.html`。双击根目录 `Check-Environment.cmd` 可只检测，不启动前后端、数据库或编译，也不会自动安装软件；检测仍会运行版本查询、依赖自检和只读 HTTP/TCP 请求，并写入报告。

报告区分：运行必需（Java 17、Node.js、项目依赖、数据库连接、端口等）、源码开发建议（VS Code、IDEA、Maven、Git）与可选功能。缺少 VS Code/IDEA/Git 不阻止运行；后端需要重编译时 Maven 3.9+ 才是必需。所有缺失项会同时列出，而不是遇到第一项即停止。数据库认证、表结构、MySQL 版本、IDE 插件和许可证仍需进一步验证。

软件从 PATH、常见安装位置和部分 Windows 安装登记查找。自定义目录、便携版本或未登记安装可能未识别，需人工确认；不宣称扫描了电脑上所有软件。报告不展示数据库密码或 AI Key。`-NoBrowser` 同时禁止自动打开报告和项目页面。

- Windows PowerShell 5.1，JDK 17，Node.js 18+，已安装项目的前端依赖。
- 后端 JAR 不存在或源码/POM 比 JAR 更新时，自动调用 PATH 中的 Maven 编译，需要 Maven 3.9+；首次可能下载依赖。
- Java 优先检查 `JAVA_HOME`、PATH，然后检查用户 `.jdks` 中的 JDK 17；不使用不兼容预览字节码的其他 Java 主版本。
- MySQL 使用现有数据库，不初始化、不重导、不清空数据。默认检查本机 3306；本机 `MySQL80` 服务停止时尝试启动，权限不足会明确提示先从 Windows 服务管理器启动它。
- 可使用后端 `smart-community-admin/.env` 配置 `MYSQL_HOST`、`MYSQL_PORT`、数据库账号及其他环境变量。格式为 `NAME=value`，支持整行注释和整值引号，不执行 shell 表达式，不做变量插值；已存在的进程环境变量优先。
- 后端在 `smart-community-admin` 目录启动，继续使用该目录已有的 `.runtime/ai-config.properties` 和 `uploads`，不移动或覆盖 AI 配置和图片。
- AI、Redis不是启动器额外安装的服务。没有可用 AI Key 不影响普通业务启动。

启动器只负责本项目的固定端口 8001/5174。端口已占用但健康检查不符合预期时停止并报错，不自动换端口或杀进程。HTTP 检查用于可用性判断，不是安全身份认证；复用本机原有服务前仍应确认其属于此项目。

## 日志与故障

启动日志位于项目 `.runtime/launcher/`，按启动时间保存。新启动的前后端分别有 `backend.out.log`、`backend.err.log`、`frontend.out.log`、`frontend.err.log` 后缀；已运行服务保留它们原来的日志位置。

启动失败时窗口会保留错误并等待按键。优先检查错误提示及日志：

| 提示 | 处理 |
| --- | --- |
| JDK / Node / Maven 缺失 | 安装所需版本并设置 PATH，重新打开启动器 |
| 前端依赖缺失 | 在 `smart-community-frontend` 执行 `npm ci` |
| MySQL 不可达 | 启动数据库服务，检查主机、端口和权限 |
| 8001 已占用或后端不健康 | 检查已有后端日志及数据库连接，不要随意结束其他进程 |
| 5174 被未知服务占用 | 确认端口占用程序后由使用者处理 |
| 后端退出/超时 | 查看后端日志，核对数据库账号、库表及 Java 版本 |
| API 代理失败 | 核对前端的后端代理与 8001 可达性 |

后端已在运行时，即使源码更新也不会擅自重启。需先确认没有进行中的业务并手动停止原后端，再启动以编译新版本。启动过程中失败时，已启动服务可能继续运行；修复后重复启动会复用，不自动回滚或结束进程。

日志可能包含后端 SQL 或运行信息，请勿公开分享未经脱敏的完整日志。启动器不是生产服务守护程序，也不负责系统开机自启、备份或进程崩溃后的自动重启。

## 命令行选项

在项目根目录运行：

```powershell
.\Start-Community.cmd -NoBrowser
.\Start-Community.cmd -CheckOnly
.\Start-Community.cmd -Rebuild
```

`-NoBrowser` 启动但不打开页面；`-CheckOnly` 只检查，不启动、编译或打开页面；`-Rebuild` 在后端尚未运行时强制重新打包。启动打包使用 `-DskipTests`，不等于执行完整测试验收。

脚本自检：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\Test-CommunityLauncher.ps1
```

移动项目目录后，项目内启动脚本仍按自身路径定位；已有桌面快捷方式需重新指向新的 `Start-Community.cmd`。
