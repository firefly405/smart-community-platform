# 模拟支付模块说明（Payment Isolation）

**日期**: 2026-03-26  
**目的**: 将「假装支付成功」从业务 Controller 中剥离，收敛到独立支付通道，避免演示逻辑与真实支付混淆。

---

## 1. 为什么要隔离

改造前：

- `BillController.pay / callback` 直接改 `paidAmount/status` 并写 `FeePayment`
- `LifeOrderController.pay` 直接 `status=1`

问题：

1. 业务代码看起来像「真支付」
2. 无法一键关闭模拟支付
3. 后续接微信/支付宝时要改散落逻辑

改造后：

```
业务 Controller
    → FeeBillPaymentService / LifeOrderPaymentService（业务落账）
        → PaymentGatewayRouter
            → MockPaymentGateway（payment.mode=mock）
            → UnsupportedRealPaymentGateway（payment.mode=real，暂未对接，直接拒绝）
```

---

## 2. 核心类（后端）

| 类 | 包 | 职责 |
|----|----|------|
| `PaymentGateway` | `com.smartcommunity.payment` | 通道抽象 |
| `MockPaymentGateway` | 同上 | **唯一**允许无真实资金返回成功的实现 |
| `UnsupportedRealPaymentGateway` | 同上 | real 模式占位，明确 501 |
| `PaymentGatewayRouter` | 同上 | 按 `payment.mode` 选通道 |
| `PaymentProperties` | 同上 | 配置绑定 |
| `PaymentRequest` / `PaymentResult` | 同上 | 统一入参/出参（含 `simulated`） |
| `FeeBillPaymentService` | `service` | 账单：调网关 → 更新账单 + 写缴费流水 |
| `LifeOrderPaymentService` | `service` | 订单：调网关 → 更新订单状态 |

日志关键字：`[MOCK-PAY]`、`[FEE-BILL-PAY]`、`[LIFE-ORDER-PAY]`

落账标记：

- 账单/订单 `remark` 追加 `[MOCK-PAY]`
- 缴费流水 `remark = 模拟支付入账（非真实资金）`
- 交易号前缀默认 `MOCK-...`

---

## 3. 配置

`application.yml`：

```yaml
payment:
  mode: ${PAYMENT_MODE:mock}          # mock | real
  mock:
    enabled: ${PAYMENT_MOCK_ENABLED:true}
    trade-no-prefix: ${PAYMENT_MOCK_PREFIX:MOCK}
    default-pay-method: 9             # 9=模拟支付
```

环境变量（见 `.env.example`）：

| 变量 | 含义 | 演示默认 |
|------|------|----------|
| `PAYMENT_MODE` | mock / real | mock |
| `PAYMENT_MOCK_ENABLED` | 是否允许模拟支付 | true |
| `PAYMENT_MOCK_PREFIX` | 交易号前缀 | MOCK |

### 推荐环境策略

| 环境 | 建议 |
|------|------|
| 本地演示 | `PAYMENT_MODE=mock` + `PAYMENT_MOCK_ENABLED=true` |
| 预发 | `PAYMENT_MOCK_ENABLED=false` 或 `mode=real`（在未接真支付前会拒绝，避免误入账） |
| 生产 | **禁止** mock；接入真实通道后再设 `mode=real` |

关闭模拟支付示例：

```bash
# 方式 A：仍是 mock 模式但禁用
set PAYMENT_MOCK_ENABLED=false

# 方式 B：切到 real（当前会 501，直到接入真通道）
set PAYMENT_MODE=real
```

## 4. API 行为变化

路径保持兼容：

| 接口 | 变化 |
|------|------|
| `POST /api/v1/fee/bill/{id}/pay` | 经网关；响应 data 含 `simulated/tradeNo/channel/...` |
| `POST /api/v1/fee/bill/callback` | 经网关 handleCallback 后再入账 |
| `PUT /api/v1/order/{id}/pay` | 经网关；响应 data 含 `simulated/tradeNo/...` |

成功消息示例：`模拟缴费成功（非真实资金）`

前端：

- 账单缴费弹窗标题改为「缴费（模拟支付）」，带警告 Alert
- 成功 Toast 展示交易号并标明模拟

---

## 5. 明确不在本模块内的逻辑

以下**不是**支付通道，仍留在原业务：

- 退款审批冲正（`RefundController` 写负向 `FeePayment`）
- 押金收取/退还
- 催缴短信（仍是占位 success）

---

## 6. 后续接真实支付时怎么做

1. 新增 `WechatPaymentGateway` / `AlipayPaymentGateway` 实现 `PaymentGateway`
2. `@ConditionalOnProperty(payment.mode=real)` 或按 channel 细分
3. `charge` 返回待支付/跳转信息；`handleCallback` 做验签
4. 业务编排服务**无需**再改 Controller 散落逻辑
5. 生产关闭 mock：`PAYMENT_MODE=real` 且不要启用 Mock bean

---

## 7. 自测清单

1. 默认配置下：账单缴费成功，`fee_payment.remark` 含「模拟支付」，`pay_trade_no` 以 `MOCK` 开头  
2. 订单支付成功，订单 `pay_trade_no` 有值，`remark` 含 `[MOCK-PAY]`  
3. `PAYMENT_MOCK_ENABLED=false` 后缴费返回业务错误（模拟已关闭）  
4. `PAYMENT_MODE=real` 后缴费返回 501（真实通道未接入）  
5. 前端 Toast/弹窗可见「模拟」提示
